# Проектирование тестов

## Назначение

Построй минимальный набор проверок, который доказывает критерии приёмки и контролирует наиболее дорогие регрессии. Количество тестов не является мерой качества покрытия.

## Когда применять

- меняются публичный контракт, расчёт, состояние, retry или обработка ошибки;
- один сценарий проходит несколько компонентов или внешних систем;
- неизвестно, какие проверки нужны на unit, integration и end-to-end уровнях;
- срок вынуждает явно приоритизировать риск.

## Входные данные

Используй acceptance criteria, изменённые контракты, impact map, инварианты, известные дефекты и ограничения среды. Для каждого ожидаемого результата укажи oracle — источник истины, а не придуманное значение.

## Порядок работы

1. Перечисли наблюдаемые риски как «условие — возможный отказ — влияние».
2. Свяжи каждый обязательный критерий и высокий риск хотя бы с одной проверкой.
3. Выбери самый низкий уровень, на котором дефект воспроизводится достоверно; оставь end-to-end только для межкомпонентных гарантий.
4. Добавь positive, boundary, negative и recovery/idempotency cases там, где они меняют риск.
5. Для stateful поведения проверь переходы, повтор, частичный сбой и конкурентное выполнение.
6. Определи fixtures, наблюдаемые сигналы, команды, среду и необходимую изоляцию.

## Результат

Передай матрицу с полями: ID риска или критерия, уровень теста, предусловие, действие, oracle, ожидаемый результат, приоритет и автоматизация. Отдельно перечисли непроверенные платформы и причины исключения.

## Остановка и эскалация

Не выдавай test plan за достаточный, если отсутствует oracle для финансового, security- или migration-поведения. Эскалируй неизвестное продуктовое правило владельцу требований. Если среда недоступна, пометь проверку `blocked`, а не `passed`.

## Типовые ошибки

| Ошибка | Коррекция |
|---|---|
| Только happy path ради скорости | Сначала покрой высокий риск отказа и необратимый эффект |
| Все сценарии проверяются end-to-end | Перенеси локальные инварианты на быстрый нижний уровень |
| Ожидаемое значение угадано тестировщиком | Сошлись на согласованный oracle или останови проверку |
| Процент покрытия заменяет traceability | Свяжи тесты с поведением и риском, а не только со строками кода |
