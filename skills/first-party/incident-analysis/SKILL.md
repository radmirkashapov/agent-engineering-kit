# Анализ инцидента

## Назначение

Восстанови причинную цепочку по доказательствам и предложи проверяемые меры предотвращения. Временная корреляция, авторитетное мнение и название команды не являются root cause.

## Когда применять

- произошёл outage, потеря или искажение данных, security event либо серьёзная регрессия;
- симптомы появились рядом с release, migration или изменением внешней системы;
- несколько отказов могли усиливать друг друга;
- требуется RCA и план предотвращения повторения.

## Входные данные

Собери сигналы с временными отметками: deploys, configuration, alerts, metrics, logs, traces, user reports, mitigation и recovery. Отдели подтверждённые факты от гипотез и отметь пробелы телеметрии.

## Порядок работы

1. Зафиксируй impact, продолжительность, затронутых пользователей и текущее состояние.
2. Построй timeline событий, наблюдений, решений и изменений системы.
3. Для каждой гипотезы укажи supporting и contradicting evidence, а также способ проверки.
4. Проследи causal chain от условия через механизм отказа к пользовательскому impact.
5. Раздели trigger, root cause, contributing factors и причины позднего обнаружения или восстановления.
6. Определи containment, corrective и preventive actions с владельцем, сроком и проверкой эффективности.

## Результат

Передай статус анализа, impact, timeline, evidence table, causal chain, подтверждённую причину либо `unknown`, contributing factors, recovery, lessons и action items. Финальный RCA должен объяснять, почему защитные барьеры не предотвратили или не обнаружили отказ.

## Остановка и эскалация

Не назначай root cause без доказательства механизма и связи с impact. При неполной телеметрии выпусти предварительный отчёт и задачу на восстановление observability. Анализ без обвинений рассматривает устройство системы и решений, а не «виновную» команду.

## Типовые ошибки

| Ошибка | Коррекция |
|---|---|
| «После release» означает «из-за release» | Проверь механизм, альтернативные гипотезы и результат rollback |
| Медленный компонент объявлен root cause | Определи, почему система не выдержала или не ограничила задержку |
| Action item звучит «быть внимательнее» | Назначь изменение системы и проверку его эффективности |
| Неполные логи заполняются догадкой | Оставь причину `unknown` и зафиксируй observability gap |
