# Доступ к корпоративным MCP

- Выбирай только возможности, необходимые для текущей задачи, и соблюдай общий бюджет инструментов и объявленные конфликты возможностей.
- Различай чтение, запись и администрирование. По умолчанию допускается только чтение; запись и администрирование требуют явного профиля доступа и проверяемого ограничения на стороне клиента или сервиса.
- Наличие возможности в каталоге не доказывает, что конкретный клиент способен ограничить инструменты сервера. При отсутствии такой проверки не активируй сервер, который может выполнять запись или администрирование.
- Получай учётные данные через OAuth, внешний брокер секретов, системное хранилище ключей или переменную окружения. Не помещай их в URL, аргументы команд, файлы Git и отчёты.
- Ограничивай обращение областью задачи, согласованным владельцем, разрешёнными узлами сети и разрешёнными классами данных. Фиксируй решение о доступе и причины отказа без записи исходных аргументов и результатов.
