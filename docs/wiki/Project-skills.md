# Репозиторий project-skills

Project-skills — общий Git-репозиторий пользовательских и проектных навыков для логического проекта. Все продуктовые репозитории с одним `project.id` получают одинаковый набор; проекты с разными ID независимы. Так команда получает единый источник инструкций, не дублируя их по каждому коду.

Kit хранит локальную управляемую копию вне продуктовых репозиториев. Исходники навыков не копируются в `.ai-team/` или отдельные проекты. Описание проекта содержит ссылку и параметры источника; удалённый Git-репозиторий остаётся источником истины.

## Подключение источника

При создании логического проекта укажите уже существующий Git-репозиторий.

```bash
agent-kit project init \
  --skills-repository-url git@gitlab.company.example:delivery/project-skills.git \
  --skills-default-branch main
```

`--skills-default-branch` применяется только вместе с URL. По умолчанию используется `main`. При интерактивном запуске без URL команда предлагает ввести его или пропустить настройку. При перенаправленном вводе и для уже существующего манифеста вопрос пропускается. Для существующего проекта укажите `skills.repository.url` и `skills.repository.default_branch` в `.ai-team/project.yaml`. Для доступа к удалённому источнику используйте SSH agent или Git credential helper.

## Добавление навыка

Из корня продуктового репозитория создайте отдельный рабочий checkout рядом с ним. `checkout` клонирует ветку из манифеста в новый или пустой каталог. Уже существующий Git checkout можно передать в `--checkout`, если его `origin` совпадает с URL манифеста.

```bash
agent-kit project skills checkout --into ../delivery-platform-skills
git -C ../delivery-platform-skills switch -c feat/23-11-2026-api-review
agent-kit project skills add \
  --from ../draft-skills/api-review \
  --checkout ../delivery-platform-skills
git -C ../delivery-platform-skills status --short
```

Для авторинга используйте только отдельный рабочий checkout. Kit отклоняет пути в продуктовых репозиториях и своём управляемом хранилище. `--from` указывает на каталог с корневым `SKILL.md`. По умолчанию ID берётся из поля `name`. Если передать `--id`, он должен совпадать с `name`. Для замены существующего пакета нужны `--replace`, чистый рабочий checkout и отслеживаемый в Git `SKILL.md`.

Kit рекурсивно импортирует дерево пакета целиком. Храните Markdown-файлы шагов, контракты, спецификации и тестовые данные внутри каталога навыка. Ссылки вроде `steps/review.md` из `SKILL.md` и `../contracts/api.yaml` из вложенного шага продолжат работать после импорта. Символические ссылки в пакете запрещены.

`add` обновляет `skills/INDEX.md` вместе с пакетом. После ручной правки пакета пересоберите индекс командой `agent-kit project skills index --checkout ../delivery-platform-skills`. Этот Markdown хранится в Git рядом с проектными навыками и перечисляет только их. Проверьте изменения, закоммитьте пакет и индекс, отправьте ветку и откройте PR/MR средствами Git и Git-платформы.

## Выбор ветки

По умолчанию используется основная ветка источника. Опубликованную рабочую ветку можно проверить локально.

```bash
agent-kit project skills status
agent-kit project skills use-branch feat/23-11-2026-api-review
agent-kit resync
```

Для возврата к ветке из манифеста выполните обе команды.

```bash
agent-kit project skills use-main
agent-kit resync
```

Выбранная ветка сохраняется локально для логического проекта, а не в Git продуктового репозитория. Публикация изменений выполняется обычными средствами Git: ветка, коммит, PR/MR и проверки. Этот порядок сохраняет привычный контроль изменений и делает версию набора воспроизводимой для участников команды.

## Приоритет и обновление

При совпадении ID приоритет растёт от встроенного навыка к внешнему каталогу, проектному набору, глобальному локальному переопределению и локальному переопределению проекта. Состояние, ревизию источника и коллизии смотрите в `agent-kit project skills status`. Итог для отдельного навыка показывает `agent-kit skills explain <id>`. Если обновление отклонено, Kit продолжает использовать ранее проверенную ревизию при её наличии.

При `resync` Kit публикует отдельный локальный каталог `<data>/installations/clients/shared/effective-skills.md` для клиентских адаптеров. Он содержит итоговый набор доступных навыков, их описания, источники, статусы и сведения о вытесненных источниках. Этот файл генерируется для текущего окружения и хранится вне Git.

## Безопасность и диагностика

- Источник и `ref` должны соответствовать схеме; не добавляйте учётные данные в URL.
- Новая версия проходит проверку до активации.
- При отсутствии сети можно работать с уже активной локальной ревизией, если она установлена.
- Изменения интерфейса проверяйте командами `agent-kit validate project-skills` и `agent-kit security scan`.
