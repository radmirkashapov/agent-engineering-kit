# Обзор: control plane и harness

Agent Engineering Kit — единый локальный набор правил и интеграций, которые можно проверять и сопровождать в Git. Один экземпляр обслуживает несколько логических проектов на одной машине.

В Kit находятся общие `rules`, роли агентов, собственные `skills`, каталоги, lock-файлы, схемы, профили и адаптеры клиентов. Конфигурация проекта может уточнить эти значения, а владелец машины — задать локальные переопределения. Утилита командной строки проверяет совместимость, вычисляет происхождение настроек и подключает возможности выбранного клиента.

## Граница ответственности

Kit является управляющим слоем и собирает действующую политику из нескольких источников. Он не запускает собственный цикл агента. Контекст, вызовы инструментов, изоляция, подтверждения, события и полный ход выполнения принадлежат внешней среде. Контракт в `catalog/clients.yaml` разделяет `managed_capabilities` и `delegated_capabilities`; выбранный контракт можно посмотреть через `agent-kit config explain`.

Kit предоставляет рабочее пространство задачи, локальную аренду путей и планирование управляемых рабочих деревьев. Это не заменяет Git, CI, запросы на слияние, очередь слияния или распределённую блокировку.

## Где хранится состояние

| Область | Что содержит |
|---|---|
| Git-репозиторий Kit | Переносимые определения и документацию |
| Установка Kit | Установленные инструменты и каноническую рабочую копию |
| Локальное состояние машины | Сеансы, блокировки, журналы, рабочие пространства задач и личные переопределения |
| Память проекта | Сводки и ссылки на интеграции конкретного `project.id` |
| Нативное состояние MCP | Базы, кэши и собственную память MCP |
| Нативное состояние клиента | OAuth, настройки и данные, которыми владеет клиент |

Секреты, локальные модели и переопределения, индексы MCP и созданные настройки клиента не должны попадать в Git. Такое разделение позволяет обновлять сам Kit, не смешивая его файлы с данными проектов и инструментов.

## Карта репозитория

- rules/, agents/, profiles/, conventions/ — общие правила, роли, разрешения и соглашения.
- skills/first-party/, catalog/, locks/ — собственные skills и закреплённые внешние компоненты.
- mcp/, clients/ — желаемая конфигурация MCP и контракты клиентов.
- src/agent_engineering_kit/ — Python CLI, capability kernel и локальное управление состоянием.
- schemas/, templates/, tests/, docs/ — контракты, шаблоны, проверки и документация.
