# Команды CLI

Встроенная справка показывает команды установленной версии и помогает не запоминать все параметры. Начните с общей формы, затем запросите справку для нужного раздела:

~~~bash
agent-kit help
agent-kit help project init
agent-kit help task lane
agent-kit help mcp docker
agent-kit help security scan
agent-kit project init --help
~~~

## Верхний уровень

| Команда | Для чего нужна |
|---|---|
| `agent-kit install` | Применить выбранную конфигурацию без обновления исходной копии |
| `agent-kit validate [target]` | Проверить описание, правила, состав и безопасность; `--ci` исключает личные настройки |
| `agent-kit doctor` | Проверить установленное окружение и доступность средств |
| `agent-kit sync` / `resync` | Привести установки, связи и адаптеры к выбранной конфигурации |
| `agent-kit project ...` | Создать и обслуживать логический проект, его копии и индексы |
| `agent-kit config explain` | Объяснить итоговые настройки, выбранный клиент и источник каждого значения |
| `agent-kit skills ...` | Посмотреть и настроить доступность навыков |
| `agent-kit mcp ...` | Управлять MCP, учётными данными и Docker MCP Toolkit |
| `agent-kit override ...` | Управлять личными переопределениями |
| `agent-kit security ...` | Устанавливать и запускать средства проверки |
| `agent-kit pr refresh` | Обновить локальный контекст запроса на слияние |
| `agent-kit run ...` | Записать условия запуска внешнего клиента |
| `agent-kit task ...` | Управлять рабочим пространством, арендой, рабочими деревьями и очередями |

Для обычной задачи предусмотрена команда `agent task create <jira-url-or-task-id>`. Короткий интерфейс `agent` поддерживает создание задачи и lane; статус, аренду, завершение и диагностику запрашивайте через `agent-kit`. В короткой команде `agent task create` нет параметра `--summary`.

## Проект и задача

Раздел проекта включает `skills`, `init`, `detect`, `status`, `attach`, `bind`, `reconcile` и `memory-refresh`. При создании проекта можно задать путь, `--id`, `--template`, `--language`, `--stack`, `--git` и `--default-branch`.

Для задач доступны `create`, `status`, `retry`, `lease`, `complete`, `release`, `gc`, `worktree-plan`, `worktree-create` и `lane`. Для параллельных частей предусмотрены `lane create`, `status`, `integrate` и `complete`. При создании задачи задаются логический проект, тип ветки, краткое описание и обязательная область записи. Планирование рабочего дерева требует префикса ветки.

## MCP, skills и overrides

Для навыков и MCP доступны просмотр состояния и полного каталога, включение, отключение, сброс, локальное переопределение и объяснение результата. Дополнительно для навыков предусмотрен откат; для MCP — формирование команды запуска, учётные данные и Docker MCP Toolkit. Docker MCP Toolkit предлагает просмотр состояния, предварительный план, применение плана, включение и отключение.

Команда `override set` принимает тип сущности и её ID, а также обязательные параметры: `--mode {extend,replace,disable}`, `--from`, `--reason` и `--scope {global,project}`. При необходимости она может выполнить последующую синхронизацию.

В `validate` доступны проверки схем, моделей, ролей, навыков, project-skills, MCP, каталогов, клиентов, профилей, соглашений, правил, переопределений, Git hygiene и безопасности. Для CI используйте `--ci`: личные источники при такой проверке исключаются.

Проверка временного проекта подтвердила команды справки для `project`, `task`, `config` и `security`, а также `project detect`, `project reconcile <PATH>`, `project status`, `config explain`, `skills list`, `mcp list`, `security status`, `validate --ci`, `doctor`, `security doctor` и `resync --no-update`. Полные наблюдения и ограничения приведены в [отчёте smoke-проверки](Smoke-test).
