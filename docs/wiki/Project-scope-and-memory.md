# Область project-skills и автоматическая память

Эта страница фиксирует baseline 4ca8be8 и обоснование доработки. Новая публикация через проверяемые загрузчики и фоновые Git-события описана в [Local-runtime-commands](Local-runtime-commands).

## Подключение существующего репозитория skills

В `.ai-team/project.yaml` задайте `skills.repository.url` и `default_branch` (полные примеры — [Project-manifest-examples](Project-manifest-examples)). Затем из корня проекта:

```bash
agent-kit resync
agent-kit project skills status
agent-kit skills list
```

Обычный resync получает выбранную удалённую ветку. Для испытания опубликованной ветки используйте `agent-kit project skills use-branch feat/27-11-2026-review`, затем resync. Возврат: `agent-kit project skills use-main`, затем resync. Изменения передаются через обычные Git commit/push и PR/MR. Собственный authoring checkout не является прямым источником неопубликованных изменений для runtime: тот получает выбранную remote branch.

Структура существующего источника должна быть такой:

```text
project-skills/
  skills/
    company-api-review/
      SKILL.md
      references/        # Необязательно
      scripts/           # Необязательно
    INDEX.md             # Индекс, не отдельный skill
```

Каждый непосредственный дочерний каталог skills обязан содержать SKILL.md. Имя каталога совпадает с name, имена уникальны; ссылки за пределы checkout запрещены. Минимальный frontmatter:

```markdown
---
version: 1
name: company-api-review
description: Review API changes for backward compatibility
requires:
  model_capabilities: [reasoning, coding]
---

Review public contracts and report breaking changes with evidence.
```

Для адаптации чужого репозитория создайте обычную ветку, перенесите каждый пакет в skills/<name>/, добавьте обязательные поля frontmatter, перенесите зависимости в references/scripts и проверьте относительные ссылки. Не вкладывайте сторонние коллекции как дополнительные уровни каталогов. Обновите индекс командой `agent-kit project skills index --checkout <path>`, выполните `agent-kit security validate <path>/skills`, затем PR/MR. После merge выполните resync и проверьте status; активация выполняется после проверки кандидата.

## Root, nested и несколько репозиториев

Поиск проекта использует ближайший `.ai-team/project.yaml`. Обычная вложенная папка без собственного manifest относится к root. Независимый nested project получает собственные id, namespace и skills.repository; parent_project — метаданные связи, автоматического наследования skills от родителя нет.

Один root manifest над несколькими репозиториями задаёт общий набор. Для самостоятельных root-копий одного logical project нужны одинаковые id и источник skills. Одинаковый id с разными источниками может вызвать проверку коллизии namespace. Разные проекты лучше описывать разными ID, даже если URL skills совпадает.

**Текущая граница реализации:** sync_clients публикует skills текущего проекта в общий `<data>/installations/clients/shared/skills`. Это не гарантирует изоляцию root/nested в одновременно открытых клиентах: следующий resync другого проекта меняет общий набор. Отдельное хранилище ревизий project-skills не устраняет проблему публикации. Не следует считать current-project инструкцию механизмом контроля доступа.

Предлагается держать global skills в общем каталоге, а project skills — в `<data>/projects/<id>/client-exposure/`; подключать их через нативные проектные механизмы каждого клиента. Root exposure должна учитывать дочерние границы: простая публикация в родительском каталоге может наследоваться nested-клиентом. Для каждого адаптера нужны тесты двух параллельных проектов и nested-переходов; при отсутствии нативной изоляции показывать ограничение вместо обещания эквивалентности.

## Когда обновляется память

Сейчас project init вызывает полную индексацию Codebase Memory и Serena для доступных репозиториев. Управляемые точки запуска обновляют память; произвольный commit из терминала не является автоматическим триггером. При недоступном или выключенном MCP результат SKIPPED означает отсутствие индексации, а не её успешное завершение.

```bash
agent-kit project memory-refresh
agent-kit doctor
```

Индексация помогает поиску, но сама по себе не заставляет модель обращаться к MCP. Нужны одновременно успешная регистрация инструментов в клиенте, правила маршрутизации и проверка реального вызова. Не обещаем автоматическое выполнение только на основании текста инструкции.

Предлагается очередь обновлений по project/repository: init → полная индексация; commit, checkout и merge → отметить HEAD как изменённый; начало агентной сессии → сравнить HEAD и состояние рабочего дерева с последней индексацией. Фоновый обработчик объединяет события и обновляет индекс под блокировкой, хранит revision/status/error. Незакоммиченные изменения учитываются отдельно. Ошибка индексации отображается явно и не отменяет уже сделанный commit.

Git hooks должны сохранять существующие пользовательские hooks и подключаться явно; одного post-commit недостаточно для checkout, merge и изменений без commit. Для worktree нужен раздельный индекс по рабочему дереву либо подтверждённая поддержка нескольких деревьев сервером. Автообновление не должно смешивать незакоммиченные изменения параллельных задач.
