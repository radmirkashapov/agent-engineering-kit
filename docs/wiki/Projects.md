# Logical projects

Логический проект объединяет один или несколько продуктовых репозиториев под стабильным `project.id`. Этот идентификатор задаёт пространство имён для локальной памяти и интеграций. Kit может работать без описания проекта, но явный проект помогает обнаруживать компоненты, связывать рабочую область из нескольких репозиториев, задавать соглашения и распределять задачи.

## Создать или подключить проект

В корне будущего проекта выполните:

```bash
agent-kit project init
```

Команда создаёт версионируемый файл `.ai-team/project.yaml`; интерактивный режим предлагает шаблон из `catalog/project-templates.yaml`. Для автоматизации:

```bash
agent-kit project init /tmp/orders --git
```

Если исходный репозиторий нельзя менять, создайте локальное описание:

```bash
agent-kit project attach /workspace/orders --id orders
```

Команда `attach` не записывает manifest в исходный репозиторий. В проекте из нескольких репозиториев используйте `project bind`, чтобы связать объявленный repository ID с локальным путём.

## Структура и компоненты

Поле `repositories` описывает Git-репозитории проекта. Kit автоматически обнаруживает компоненты по файлам сборки Maven, Gradle, Node.js, Go, Cargo, .NET, Python и Bazel. Обычно `components` не требуется; добавляйте уточнения для владельца, критичности или дополнительной логической границы. Настройки интеграций, например Jira, хранятся в manifest; секреты туда не помещают.

Проверяйте обнаруженную структуру и локальное состояние:

```bash
agent-kit project detect /tmp/orders
agent-kit project reconcile /tmp/orders
agent-kit project reconcile /tmp/orders --apply
agent-kit project status /tmp/orders
agent-kit config explain /tmp/orders
```

Команда `reconcile` принимает путь к проекту, не его ID. Она показывает различия между обнаруженной структурой и описанием проекта; параметр `--apply` сохраняет обнаруженный состав в локальном состоянии машины. Возможные состояния включают `READY`, `DEGRADED`, `BLOCKED` и `MISMATCHED`. Отсутствующий обязательный репозиторий нельзя незаметно исключить из анализа влияния.

## Несколько репозиториев и индексы

Работайте от корня логического проекта. Определяйте компонент через `repositories[].path` и `components[].path`. Git-команды выполняются отдельно в каждом репозитории. Если обязательной копии нет, выполните `project bind`, затем повторите проверку состояния и состава.

При создании проекта Kit индексирует доступные репозитории через Codebase Memory и Serena. Smoke-проверка подтвердила, что `project memory-refresh` может завершиться с кодом 0 и статусом `SKIPPED`, если MCP отключены или исполняемые файлы недоступны. Это означает, что индексация не выполнялась; проверьте MCP и запустите команду повторно после их настройки. Подробности — в [памяти](Memory) и [отчёте проверки](Smoke-test).
