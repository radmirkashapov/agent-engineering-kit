# Устранение неполадок

Начните с диагностики и объяснения effective-конфигурации:

```bash
agent-kit doctor
agent-kit config explain .
agent-kit project status .
agent-kit mcp status
agent-kit skills status
```

## MCP сообщает AUTH_REQUIRED

Для stdio проверьте `agent-kit mcp creds status`, импортируйте нужные значения через `agent-kit mcp creds import --from <env-file>` и перезапустите клиент. В smoke-проверке отсутствовали токены GitHub, Sentry и SonarQube; `SENTRY_HOST` необязателен. Для удалённого MCP завершите OAuth в том же клиенте и профиле, где запрашиваете инструмент. Очистка локального хранилища не удаляет OAuth-состояние клиента или Docker Desktop.

`Context7` может показывать `AUTH_REQUIRED`, пока OAuth не пройден в нужном клиенте и профиле. Это состояние авторизации интеграции; оно само по себе не указывает на ошибку установки.

## Изменение не видно в клиенте

Проверьте effective source через agent-kit config explain, затем выполните подходящий agent-kit resync. Если менялся checkout Kit, запустите bootstrap из нужной копии и перезапустите долгоживущие клиенты. Для MCP проверьте capability contract и выбранный профиль; запрошенное разрешение не означает, что клиент его применил.

## Project status показывает отсутствующий repository

Сверьте manifest и локальные пути. В multi-repo проекте привяжите clone командой agent-kit project bind, затем проверьте project status и project reconcile. Не исключайте обязательный repository из анализа влияния.

## Task находится в WAITING

agent-kit task status показывает конкурирующий task и пересекающиеся пути. Не записывайте файлы, пока write set заблокирован. Разделите области или работайте по очереди; lease защищает только текущую машину.

## task complete вернула ошибку после завершения

В smoke-проверке для workspace без разрешённого logical project команда записала статус completed, затем вернула ошибку при последующем обновлении памяти. Сначала проверьте состояние через `agent-kit task status <TASK>`; если workspace уже завершён, выполните `agent-kit task release <project-id> <TASK>`. После удаления управляемых рабочих деревьев можно запустить `agent-kit task gc <project-id> <TASK>`. Подробность и точный пример — в [отчёте smoke-проверки](Smoke-test).

## Project skills не обновляются

Проверьте agent-kit project skills status, сетевую доступность и выбранную ветку. При сбое сети продолжайте с ранее активной ревизией; candidate без успешной проверки не активируйте. Сверяйте доступные команды через agent-kit help project skills.

## Индексы памяти устарели или неполны

После внешних изменений исходников запустите `agent-kit project memory-refresh`. Если команда завершилась с кодом 0 и статусом `SKIPPED` для Codebase Memory или Serena, индексация не выполнялась: проверьте, включены ли MCP и доступны ли их исполняемые файлы. Убедитесь, что нужные репозитории привязаны. Отчёт индексации находится в локальной памяти, он не входит в Git.

## Security scan завершился ошибкой

Статус `FAIL` из-за findings во внешних skills требует ручного разбора; он не означает, что установка Kit сломана. Проверьте сводку [smoke-проверки](Smoke-test), просмотрите findings и при необходимости настройте ключи semantic analyzers. Не трактуйте такой результат как чистый и не копируйте секреты в диагностику.

При передаче проблемы приложите команду и версию Kit, статус и безопасный фрагмент вывода. Удалите лишние абсолютные пути и данные.
