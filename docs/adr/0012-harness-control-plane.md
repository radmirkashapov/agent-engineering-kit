# ADR 0012: Kit как control plane для внешних agent harness

Статус: принято.

## Контекст

Codex, Claude Code, Claude Desktop, OpenCode и Cline имеют собственные циклы выполнения, правила контекста, sandbox, approvals и жизненный цикл задач. Попытка повторить эти механизмы внутри Kit создала бы второй runtime, усложнила поддержку и размыла владельца состояния.

Одновременно Kit уже управляет переносимыми правилами, ролями, skills, MCP, моделями, overrides и адаптерами. Эту границу необходимо описывать и проверять явно.

## Решение

`agent-engineering-kit` является control plane и компилятором effective policy. Клиент остаётся владельцем execution loop. Каталог клиентов содержит проверяемый capability contract с двумя группами:

- `managed_capabilities` — инструкции, skills и MCP, которые Kit способен материализовать;
- `delegated_capabilities` — agent loop, context window, sandbox, approvals, task lifecycle и event stream, которыми владеет клиент.

Логический проект может указать предпочтительный клиент и обязательные управляемые возможности. Режим `auto` выбирает первый совместимый адаптер. `config explain` показывает разрешённый контракт, а `resync` сохраняет его вместе с хешем effective policy.

Оркестрация очередей, worktree, повторных запусков и Pull Request не входит в `resync` и при необходимости создаётся отдельным слоем.

## Последствия

- Пользователь видит, какие возможности действительно обеспечивает Kit, а какие зависят от клиента.
- Конфигурация не обещает sandbox или approvals только на основании наличия YAML-адаптера.
- Состояние сеанса можно сопоставить с точной ревизией и effective policy.
- Добавление нового клиента требует явного capability contract и schema validation.
- Унифицированный orchestrator можно развивать независимо, не меняя обязанности control plane.
