# Подготовка корпоративных и проектных навыков

## Статус

Предложено и согласовано для реализации.

## Контекст и цель

Agent Engineering Kit уже читает навыки из встроенного корпоративного слоя, внешнего каталога, отдельного Git-репозитория `project-skills` и локальных переопределений. Автору приходится вручную копировать навык в нужную рабочую копию Git. У существующей команды `project init` отсутствует интерактивная настройка источника проектных навыков. Агентам также нужен компактный каталог доступных навыков с указанием их источников.

Kit подготавливает и проверяет файлы. Автор создаёт ветку, коммитит, отправляет и открывает PR/MR средствами Git и Git-платформы.

## Границы и инварианты

- Встроенный корпоративный навык принадлежит форку Kit и хранится в `skills/first-party/<id>/`.
- Внешний корпоративный пакет объявляется через `catalog/skills.yaml` и `locks/skills.lock.yaml`. Исходники остаются во внешнем репозитории.
- Проектный навык хранится в отдельном Git-репозитории, указанном в `.ai-team/project.yaml`.
- Рабочую копию `project-skills` можно создать в соседнем каталоге, например `../delivery-platform-skills`.
- Управляемая копия в каталоге данных предназначена для синхронизации. Команды импорта и индексации проектных навыков отклоняют её как место записи.
- Ветка, коммиты, push, PR/MR, слияние и создание удалённого репозитория остаются задачами Git и Git-платформы.
- `SKILL.md` и его метаданные проверяются до записи. Имена исходного и целевого каталогов точно совпадают с полем `name` и со значением `--id`, если оно передано.
- Для перезаписи существующего каталога требуется явный `--replace`.

## Решение

### Встроенный корпоративный навык

Добавить:

```text
agent-kit skills add --from <directory> [--id <id>] [--replace]
```

Команда принимает каталог навыка, проверяет пакет, копирует его в `skills/first-party/<id>/` активной копии Kit и показывает получившийся путь. Идентификатор берётся из поля `name`. Переданное значение `--id` должно с ним совпадать. После копирования команда проверяет целевой каталог и печатает команды для последующей проверки. Автор отдельно запускает `resync` и добавляет файлы в индекс Git.

### Проектный навык

Добавить:

```text
agent-kit project skills checkout --into <empty-directory>
agent-kit project skills add --from <directory> --checkout <directory> [--id <id>] [--replace]
agent-kit project skills index --checkout <directory>
```

`checkout` читает URL `project-skills` из манифеста логического проекта и клонирует репозиторий в явно указанный новый или пустой каталог. Команды `add` и `index` принимают корень самостоятельной Git-копии со своим каталогом `.git` и проверяют совпадение нормализованного `origin` с URL манифеста. Kit отклоняет связанные копии, созданные через `git worktree add`, даже при совпадающем `origin`. Рабочая копия должна находиться за пределами продуктовых репозиториев и управляемого хранилища. `add` копирует пакет в `<checkout>/skills/<id>/` и обновляет `skills/INDEX.md`.

Пакет импортируется целиком. Вместе с корневым `SKILL.md` рекурсивно копируются Markdown-файлы шагов, контракты, спецификации, тестовые данные и обычные подкаталоги, включая пустые. Относительные ссылки из `SKILL.md` и вложенных Markdown-файлов продолжают разрешаться внутри пакета. Символические ссылки запрещены во всём дереве.

`index` пересобирает `skills/INDEX.md` по корректным дочерним `SKILL.md`. Команда подходит для обновления после ручных правок и проверки актуальности индекса в CI.

Команды проектного импорта требуют настроенный `skills.repository`. Сообщение об ошибке объясняет, как добавить URL через `project init` или манифест.

### Настройка при `project init`

Добавить параметры для неинтерактивного запуска.

```text
--skills-repository-url <git-url>
--skills-default-branch <branch>   # default: main; допустим только вместе с URL
```

В интерактивном терминале без переданного URL команда `project init` один раз предлагает пропустить настройку или ввести URL `project-skills`. Вопрос пропускается при перенаправленном вводе, переданном URL или уже существующем манифесте. Для создания соседней рабочей копии используется отдельная команда `project skills checkout`.

После создания манифеста `project init` один раз вызывает `ProjectMemoryManager.index(..., mode="full")`. Для каждого продуктового репозитория менеджер запускает доступные индексаторы. Codebase Memory MCP получает `--mode full`. Serena выполняет обычный `project index` без параметра режима. Ошибка доступного индексатора прерывает инициализацию. Отсутствующий или отключённый MCP отмечается как `SKIPPED`.

### Индексы для агентов

Используются два каталога навыков.

1. `project-skills/skills/INDEX.md` хранится в Git. Он перечисляет проектные навыки с их ID, описанием и путём. Его обновляют `project skills add` и `project skills index`.
2. `effective-skills.md` генерируется при `resync` и хранится в локальном каталоге клиентских установок вне Git. Он перечисляет доступные встроенные навыки, внешние пакеты, проектные навыки и локальные переопределения с указанием источника, статуса и происхождения.

Сгенерированные адаптеры получают путь к индексу. При совпадении ID строка отображает итоговый источник и список вытесненных источников.

Docker MCP Toolkit остаётся необязательной интеграцией. Если Docker или Toolkit недоступен либо ранее применённый профиль не проходит проверку, `resync` восстанавливает нативную маршрутизацию, сообщает о пропуске Toolkit и продолжает работу. Ошибки обязательной нативной установки или регистрации MCP прерывают `resync`.

## Ошибки и восстановление

- До записи команда отклоняет каталог без рабочей копии Git, несовпадающий `origin`, неверный `SKILL.md`, выход за разрешённые границы каталогов, символические ссылки и конфликты ID.
- Копирование использует соседний временный каталог и атомарную замену. При ошибке сохраняются прежний пакет и `INDEX.md`.
- `--replace` требует чистую рабочую копию и отслеживаемый `SKILL.md`. Предыдущее содержимое восстанавливается из Git.
- Повторный `index` сортирует строки по ID и даёт тот же результат при неизменном наборе пакетов.

## Проверяемые критерии

| Условие | Действие | Наблюдаемый результат |
|---|---|---|
| Корректный навык вне Kit | `skills add` | В рабочей копии появляется только `skills/first-party/<id>` |
| Имя исходного каталога отличается от поля `name` | `skills add` или `project skills add` | Отказ до записи, в том числе при переданном `--id` со значением `name` |
| Некорректный или конфликтующий ID встроенного навыка | `skills add` без `--replace` | Ошибка до записи |
| Настроенный источник и пустой соседний каталог | `project skills checkout` | Создана рабочая копия Git с правильным `origin` |
| Управляемая копия или продуктовый репозиторий | `project skills add --checkout` | Отказ без изменения файлов |
| Связанная рабочая копия с совпадающим `origin` | `project skills add --checkout` или `project skills index --checkout` | Отказ без изменения файлов |
| Корректный проектный навык | `project skills add` | Пакет и детерминированный `skills/INDEX.md` обновлены вместе |
| Составной навык | `skills add` или `project skills add` | Сохранены вложенные Markdown-файлы, контракты, спецификации и относительные ссылки внутри пакета |
| Интерактивный запуск без URL | `project init` | Предлагает указать URL или пропустить настройку и сохраняет введённый URL в манифесте |
| Перенаправленный ввод или явный URL | `project init` | Вопрос пропущен. Манифест соответствует аргументам |
| Новый манифест проекта | `project init` | Менеджер вызывается с `mode="full"`. Для каждого репозитория доступный Codebase Memory получает `--mode full`, а Serena выполняет `project index`. Отчёт сохранён в локальном состоянии |
| Синхронизация клиентов | `resync` | Опубликован индекс доступных навыков с указанием источников |
| Docker или Toolkit недоступен либо профиль не прошёл проверку | `resync` | Маршрутизация MCP возвращается к нативной. Отчёт отмечает пропуск Toolkit |

## Вне области

- API Git-платформы, создание удалённых репозиториев и веток, коммиты, push и PR/MR.
- Автоматическое добавление отдельной рабочей копии в рабочее пространство проекта или метаданные Git.
- Копирование пакетов из внешнего каталога в Kit.
- Изменение правил локальных переопределений и приоритета источников.
