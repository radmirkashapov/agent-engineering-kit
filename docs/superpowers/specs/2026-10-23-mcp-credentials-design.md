# Дизайн безопасной загрузки credentials для MCP

## Статус

Согласовано пользователем 23 октября 2026 года. Документ описывает импорт локального env-файла, безопасный запуск stdio MCP и границы OAuth для разных клиентов.

## Контекст

Реестр MCP уже хранит только ссылки вида `env:VARIABLE`, но `agent-kit resync` не загружает env-файл и не передаёт значения в нативные регистрации клиентов. Сейчас stdio MCP получает секрет только из окружения процесса AI-клиента. Это неудобно для GUI-клиентов и провоцирует запись literal values в конфигурации клиентов.

OAuth MCP не используют общий env-файл. Codex, Claude Code, Claude Desktop, OpenCode и Cline владеют собственным нативным OAuth state, поэтому авторизация выполняется отдельно в каждом клиенте, который подключается к remote MCP. Если несколько клиентов подключены только через один Docker MCP Gateway, OAuth state может принадлежать Docker Desktop, но Kit не копирует и не экспортирует его.

## Цели

- предоставить tracked-шаблон `mcp-creds.example.env` без значений;
- разрешить импорт доверенного `mcp-creds.env` в machine-local хранилище;
- не сохранять значения в Git, effective policy, JSON state, журналы и конфигурации клиентов;
- передавать credentials stdio MCP только в момент запуска процесса;
- показывать наличие обязательных переменных без раскрытия значений;
- сохранить нативный OAuth для remote MCP;
- документировать включение MCP и авторизацию в каждом поддерживаемом клиенте.

## Не входит в объём

- синхронизация секретов между компьютерами;
- экспорт OAuth token или cookie из одного клиента в другой;
- собственное шифрование вместо системного secret store;
- автоматический импорт произвольного shell-кода;
- запись credentials в Docker URI, аргументы процесса или YAML.

## Рассмотренные варианты

### Literal values в конфигурациях клиентов

Отклонён: значения остаются в TOML, JSON или пользовательских настройках клиентов и могут попасть в диагностику или резервную копию.

### `source mcp-creds.env` перед запуском клиента

Остаётся допустимым ручным обходным путём, но не является механизмом Kit: shell-файл способен выполнять код, GUI-клиенты не наследуют окружение терминала, а ротация зависит от пользователя.

### Machine-local vault и launcher

Выбранный вариант. Kit строго разбирает env-файл как данные, атомарно сохраняет разрешённые значения в `<data>/secrets/mcp-creds.env`, ограничивает права файла и регистрирует для stdio MCP launcher. Launcher читает vault непосредственно перед запуском сервера и передаёт значения только через environment дочернего процесса.

## Пользовательский контракт

В корне Kit поставляется `mcp-creds.example.env`. Локальный файл `mcp-creds.env` находится в `.gitignore`.

```bash
cp mcp-creds.example.env mcp-creds.env
# Пользователь заполняет только нужные значения.
agent-kit mcp creds import --from ./mcp-creds.env
agent-kit mcp creds status
agent-kit resync --no-update
```

Команды:

- `agent-kit mcp creds import --from <path>` — проверить и атомарно импортировать файл;
- `agent-kit mcp creds status` — вывести для каждого объявленного имени только `SET`, `MISSING` или `OPTIONAL`;
- `agent-kit mcp creds clear` — удалить machine-local vault после явного подтверждения `--yes`.

Импорт принимает пустые строки, комментарии и строки `NAME=VALUE`. `export`, shell expansion, command substitution, дублирующиеся имена, некорректные идентификаторы и переменные, не объявленные effective MCP definitions, отклоняются. Пустое значение означает отсутствие секрета. Значения не выводятся даже при ошибке.

## Хранение и права

Канонический файл располагается в `<data>/secrets/mcp-creds.env`, то есть вне Git checkout и project memory. Запись атомарна. В POSIX файл получает режим `0600`, каталог — `0700`. В Windows используется machine-local data root текущего пользователя; Kit не ослабляет существующие ACL и сообщает ошибку, если файл нельзя безопасно создать или заменить.

State хранит только имена переменных, время импорта и статусы наличия. Хэш или длина значения не сохраняются, чтобы не создавать дополнительный идентификатор секрета.

## Разрешённые переменные

Список строится из effective MCP definitions: ключей `environment`, ссылок `env:VARIABLE` и `required_environment`. Поэтому корпоративный или локально переопределённый MCP может объявить собственный `JIRA_API_TOKEN`, но импорт не принимает неизвестное имя заранее.

`mcp-creds.example.env` содержит переменные базового каталога. Для официальных Atlassian, GitLab и Context7 используются комментарии про OAuth вместо фиктивного token-поля.

## Launcher для stdio MCP

Для stdio MCP с `environment` Kit генерирует стабильный launcher в `<data>/installations/clients/shared/mcp-launchers/`. Конфигурация клиента содержит абсолютный путь launcher и обычные аргументы MCP, но не значения secrets.

Уточнение после итогового review: контракт v2 дополнительно сохраняет canonical абсолютный `data_home`, выбранный при регистрации. Launcher проверяет схему и путь и читает vault из этого data home независимо от окружения GUI-клиента. Контракт v1 остаётся читаемым с прежним разрешением пути из окружения; повторная регистрация обновляет его до v2. Импорт, чтение, удаление и подготовка `secrets` запрещают symlink/reparse points. POSIX удерживает directory descriptors и применяет no-follow операции, Windows удерживает handles, запрещающие подмену компонентов. Режимы доступа и Windows ACL сохраняют прежние гарантии.

Для ручной регистрации предусмотрена `agent-kit mcp launch-command <id>`: она применяет effective access profile, требует включённый установленный stdio MCP и печатает только JSON `command`/`args`. При credential-переменных создаётся тот же launcher-контракт, иначе возвращается прямая команда. Установленные Codex и Claude Code не требуются; remote OAuth остаётся нативным. Исполняемые примеры преобразования результата в конфигурацию Claude Desktop, OpenCode и Cline находятся в соответствующих client runbooks.

При запуске launcher:

1. загружает effective definition по ID;
2. строго разбирает machine-local vault;
3. проверяет `required_environment`;
4. создаёт дочернее environment только с объявленными отображениями;
5. заменяет процесс реальной командой MCP;
6. при отсутствии обязательной переменной завершает работу с сообщением, содержащим только её имя.

Credentials наследуются только конкретным MCP-процессом. Остальные MCP и AI-клиент не получают их через сгенерированную конфигурацию.

Ротация значения не требует `resync`: следующий запуск MCP прочитает обновлённый vault. Изменение списка переменных или команды MCP требует `resync`.

## Регистрация и OAuth по клиентам

`resync` автоматически управляет namespaced registrations Codex CLI и Claude Code, если соответствующий executable найден. Claude Desktop, OpenCode и Cline получают `CONFIG_REQUIRED` и настраиваются по их client runbook до появления безопасного нативного адаптера.

Remote OAuth MCP регистрируется URL без token. Первый вызов или встроенная команда клиента запускает OAuth flow. OAuth state принадлежит клиенту, поэтому новый клиент или новый пользовательский профиль авторизуется отдельно. Kit показывает `AUTH_REQUIRED`, но не читает и не переносит OAuth credentials.

## Ошибки и диагностика

- неизвестная переменная: импорт отклоняется с её именем;
- небезопасный синтаксис env: импорт отклоняется без вывода строки целиком;
- отсутствует required secret: `status` и `doctor` сообщают имя, launcher не стартует сервер;
- отсутствует optional secret: статус остаётся `OPTIONAL`;
- OAuth не завершён: registration получает `AUTH_REQUIRED`;
- vault повреждён или имеет небезопасные POSIX permissions: запуск блокируется;
- вывод `doctor`, `config explain` и generated state проходит существующую redaction.

## Влияние на существующие контракты

- `mcp/registry.yaml` и локальные MCP overrides сохраняют формат `env:VARIABLE`;
- `register_native_mcp` меняет команду только для stdio MCP с environment;
- MCP без environment и remote OAuth MCP сохраняют текущую регистрацию;
- Docker arguments вида `-e VARIABLE` сохраняются, значение добавляется launcher через process environment;
- существующие пользователи без vault продолжают работать, если секрет уже экспортирован в окружение клиента; vault имеет приоритет только для объявленных непустых значений;
- `.env.example` сохраняется для обратной совместимости, а `mcp-creds.example.env` становится специализированным шаблоном MCP.

## Проверка

- parser не выполняет shell-код и не раскрывает значения в исключениях;
- импорт принимает только effective allowlist имён и ставит безопасные permissions;
- generated registrations не содержат literal secrets;
- launcher передаёт обязательные переменные только дочернему MCP;
- missing required variable завершает launcher до запуска сервера;
- OAuth registrations не проходят через vault;
- Codex и Claude Code получают launcher, остальные клиенты сохраняют `CONFIG_REQUIRED`;
- git hygiene отклоняет tracked/staged `mcp-creds.env`;
- README описывает импорт, ротацию, включение MCP, OAuth и security scan.
