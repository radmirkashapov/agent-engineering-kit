# Централизованная регистрация пользовательских моделей

## Цель

Дать пользователю один каталог моделей Agent Engineering Kit и безопасно
синхронизировать из него доступные OpenAI-compatible provider и модели в
поддерживаемые нативные клиенты. Ключи, OAuth-токены и любые другие секреты
не являются частью этой функции.

## Границы и источники данных

`models/corporate.yaml` и machine-local
`<data>/overrides/models.yaml` остаются входными каталогами. У provider и
model появляются необязательные описательные поля: `name`, `description`,
`base_url`, `api_key_env`, `wire_api`, а также технические параметры модели
`model_id`, `context_window` и `max_output_tokens`. Значения в локальном
каталоге расширяют корпоративные, как и сегодня.

`api_key_env` — только имя переменной окружения. Его значение никогда не
читается, не записывается и не попадает в журналы, generated state или CLI.
Если клиент уже содержит literal key, Kit оставляет его байт-в-байт и
показывает предупреждение. Kit не создаёт backup такого файла, так как это
было бы вторым незащищённым экземпляром секрета.

## Матрица клиентов

| Клиент | Режим | Изменяемые поля | Секреты |
| --- | --- | --- | --- |
| Codex | `managed` | custom provider, `base_url`, `wire_api`, выбранная модель | сохраняется существующий `env_key`; новый берётся только как имя `api_key_env` |
| OpenCode | `managed` system layer | custom provider, `settings.baseURL`, `models` | пользовательский `opencode.json`/`opencode.jsonc` не открывается; Kit использует официальный system-level config |
| Cline | `manual` | нет | внутреннее provider storage не редактируется |
| Claude Code | `manual` | нет для OpenAI-compatible API | env и авторизация Claude не редактируются |
| Claude Desktop | `unsupported` | нет | модельная авторизация не редактируется |

Для Codex Kit владеет лишь provider, помеченным metadata-файлом в собственном
состоянии. Для OpenCode Kit создаёт отдельный официальный system-level config,
который OpenCode объединяет с пользовательским файлом и применяет с более
высоким приоритетом. Пользовательский файл не читается. При нехватке прав
возвращается `CONFIG_REQUIRED`. Чужой provider с тем же ID — конфликт: команда не
изменяет его и завершает работу с понятной ошибкой. Запись атомарна, но
резервную копию не создаёт: она могла бы продублировать literal credentials.
Повторная синхронизация идемпотентна.

## CLI и состояние

Добавляется группа `agent-kit models`:

- `list` — объединённый каталог с description;
- `status` — матрица клиентов и зарегистрированные provider;
- `sync [--client CLIENT]` — применить только безопасные управляемые
  изменения;
- `explain CLIENT` — объяснить режим, конфигурационный путь и способ
  аутентификации без раскрытия значений.

`agent-kit resync` вызывает ту же синхронизацию после публикации client
adapters. Отсутствующий клиентский файл не считается ошибкой: `sync` создаёт
минимальный конфиг только для Codex/OpenCode. Отсутствие `api_key_env` не
блокирует регистрацию модели, но отмечается как `credentials_required`.

## Ошибки и безопасность

Неподдерживаемый клиент возвращает статус без мутации. Невалидный URL,
неполный provider или конфликт ownership приводят к ошибке до записи файла.
Все сообщения содержат лишь идентификатор provider и имя переменной, но не
её значение.

## Проверка

Тесты покрывают валидацию расширенного каталога, Codex TOML, OpenCode JSONC,
сохранение ключевых полей, backup, идемпотентность, conflict ownership,
режимы Cline/Claude и CLI. Полный `pytest` и `agent-kit validate --ci`
подтверждают совместимость с существующим репозиторием.
